# 04. Мастер настройки и первый вход

## 1. Открыть браузер

Введите `https://ИМЯ_ИЛИ_IP/` (или `http://…` в лаборатории).  
Если установка не завершена, откроется `/setup/`.

## 2. Шаги мастера (9)

| # | Шаг | Что сделать |
|---|---|---|
| 1 | Лицензия | Загрузить `.novalic`, указать URL License Server, сверить fingerprint |
| 2 | Организация | Имя + префикс локальных ID (не CVE/BDU), превью `ACME-2026-0001` |
| 3 | Оформление | Логотип, заголовок и текст страницы входа |
| 4 | База данных | Подключиться **или** создать УЗ PostgreSQL + GRANT |

| 6 | Источники | NVD key, KEV, БДУ, расписание |
| 7 | Почта | SMTP (можно заполнить позже в настройках) |

## 3. Подключение БД — режимы A и B

**УЗ PostgreSQL ≠ пользователь веб-интерфейса VULNDB.**

### Режим A — подключиться к существующей БД

Используйте, если уже выполнили SQL из [02_STACK_INSTALL.md](02_STACK_INSTALL.md) или Compose создал роль.

1. Host `127.0.0.1`, Port `5432`, DB `vulndb`, user `vulndb`, пароль.  
2. Нажмите **«Проверить подключение»** — должно быть `SELECT 1 · OK`.  
3. **«Сохранить и продолжить»** — `DATABASE_URL` пишется в `.env`, выполняется `migrate` при пустой схеме.

### Режим B — создать УЗ и базу

Нужен пароль суперпользователя PostgreSQL (`postgres`). Он **не сохраняется** после шага.

Мастер выполнит эквивалент `CREATE USER` / `CREATE DATABASE` / `GRANT`.

### Если мастер не смог

Создайте вручную (см. шаг 02) и вернитесь в режим A.

| Право | Зачем |
|---|---|
| CONNECT / CREATE на БД | миграции Django |
| ALL на schema `public` | таблицы/индексы |
| DEFAULT PRIVILEGES на tables/sequences | будущие объекты |

## 4. Администратор VULNDB

Создайте учётную запись с ролью `platform_admin`. Запомните логин/пароль.

## 5. После финиша

1. Откроется страница входа.  
2. Войдите администратором.  
3. Синхронизацию NVD смотрите в **Настройки → Синхронизации** (`/settings/#sync`).  
4. При ошибках NVD API в лаборатории приложение может подставить демо-записи CVE.
